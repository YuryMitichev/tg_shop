# AI-импорт каталога из Telegram

Функция включается feature flag и по умолчанию не работает ни для одного
магазина. AI получает только текст поста; Telegram-фотографии хранятся как
`file_id` и прикрепляются к товару после решения владельца.

## Включение и поэтапный rollout

1. Применить миграции: `alembic upgrade head`.
2. Заполнить `OPENAI_API_KEY`. `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и
   авторизованная `TELEGRAM_SESSION` нужны для backfill и счётчиков просмотров.
3. Установить `CHANNEL_IMPORT_ENABLED=True`. Для ограниченного rollout также
   задать `CHANNEL_IMPORT_PILOT_SHOP_ID=<id магазина>`. Для общего релиза не
   задавать `CHANNEL_IMPORT_PILOT_SHOP_ID`.
4. Перезапустить bot-контейнер.
5. В боте магазина выполнить `/connect_channel`, выбрать канал и убедиться,
   что бот является его администратором.

`TELEGRAM_SESSION` используется для backfill последних 50 публикаций и
периодического чтения накопительных просмотров товарных постов.
Realtime-посты и правки приходят через Bot API.
Если MTProto-секреты отсутствуют, канал подключается в режиме realtime-only и
не делает неудачных попыток исторического импорта.

Получите `API_ID` и `API_HASH` в разделе **API development tools** на
`my.telegram.org`, затем локально выполните:

```bash
python scripts/generate_telegram_session.py
```

Скрипт скрывает ввод `API_HASH`, не принимает секреты через аргументы командной
строки и не записывает их на диск. Полученную `StringSession` храните как пароль:
она предоставляет доступ к Telegram-аккаунту.

## Поток и статусы

Пост сохраняется в PostgreSQL, проходит консервативный локальный префильтр и
лишь затем — при наличии бюджета — отправляется в Responses API. Очевидные
нетоварные публикации получают `non_product`; фото без подписи —
`needs_manual`. При сомнении пост не отбрасывается.

Задания: `queued`, `analyzing`, `completed`, `failed`, `budget_blocked`,
`subscription_blocked`, `superseded`. Просроченное `analyzing`-задание после
перезапуска автоматически подхватывается другим worker. Черновики:
`pending`, `needs_manual`, `possible_duplicate`,
`approved`, `rejected`, `duplicate_skipped`, `superseded`.

Подтверждение создаёт категорию, определения новых характеристик, товар,
варианты, фото и ссылку на Telegram-источник одной транзакцией. Нужны название,
категория, целая цена в RUB и остаток каждого варианта.

## Эксплуатация

- Два AI-задания выполняются одновременно, не более одного на магазин.
- Timeout — 45 секунд; повторы через 5, 30 и 120 секунд с jitter.
- Месячный бюджет каждого магазина задаёт `CHANNEL_IMPORT_BUDGET_USD`; расходы
  и лимит изолированы по `shop_id`. После исчерпания задания сохраняются как
  `budget_blocked` и могут быть повторены из админки.
- Сырые данные отклонённых и нетоварных постов очищаются через 90 дней.
- API расположен под `/api/admin/channel-import`, интерфейс — `/channel-import`.

## Кнопки товаров в публикациях

Кнопки включаются отдельно от AI-импорта:

```env
CHANNEL_PRODUCT_BUTTONS_ENABLED=True
CHANNEL_PRODUCT_BUTTONS_PILOT_SHOP_ID=<id магазина>
```

Для общего релиза удалите `CHANNEL_PRODUCT_BUTTONS_PILOT_SHOP_ID`, сохранив
глобальный feature flag: это откроет настройку всем магазинам, но не изменит
старые публикации без явного действия владельца.

До включения настройте для бота магазина Main Mini App через BotFather и
выдайте боту в канале право редактировать публикации. Готовность обоих условий
видна на странице `/channel-import`.

Поток синхронизации:

```text
подтверждение или ручная привязка
  → ProductSourceRef + queued job (одна транзакция)
  → проверка актуальной версии, Main Mini App и прав канала
  → сбор исходных URL-кнопок + одной кнопки на активный товар
  → edit_message_reply_markup
  → completed | retry_wait | needs_action
```

Стабильный ключ внешнего действия — `(post_id, button_version)`. Новая версия
помечает ожидающие старые задания как `superseded`, а worker всегда собирает
клавиатуру заново, поэтому повтор не создаёт дубликаты. Временные ошибки и
rate limit повторяются через 5, 30, 120, 600 и 1800 секунд с jitter. После
исчерпания попыток, при отсутствии Main Mini App или прав канала задание
переходит в `needs_action`; товар при этом остаётся опубликованным.

Для восстановления исправьте указанную в панели причину и нажмите «Повторить
установку». У старых постов без сохранённой исходной клавиатуры требуется
отдельное подтверждение замены: это защищает сторонние кнопки от молчаливого
удаления. Отключение feature flag останавливает новые Telegram-изменения, не
затрагивая каталог и AI-импорт.

## Подтверждённые продажи и эффективность публикаций

Единый источник истины для выручки — поля `orders.payment_confirmed_at`,
`payment_confirmation_source` и `payment_confirmation_ref`. Они заполняются
идемпотентно успешным webhook (`online`) или явным переводом заказа в статус
`paid` менеджером (`manual`). Повторный webhook и ручная отметка того же заказа
не создают вторую продажу. Отменённый заказ не входит в выручку, даже если до
отмены был оплачен.

```text
кнопка поста с ref-токеном
  → проверенный Mini App launch
  → product_open (идемпотентный event_key)
  → source_post_id в позиции корзины
  → source_post_id в позиции заказа
  → payment_confirmed_at
  → выручка конкретной публикации
```

Атрибуция включается отдельно и может быть ограничена одним магазином на этапе
rollout:

```env
CHANNEL_ATTRIBUTION_ENABLED=True
CHANNEL_ATTRIBUTION_PILOT_SHOP_ID=<id магазина>
```

Для общего релиза удалите `CHANNEL_ATTRIBUTION_PILOT_SHOP_ID`.

Токен ссылки разрешается только на backend и обязан соответствовать магазину,
товару и `ProductSourceRef`. События имеют уникальность
`(shop_id, event_type, event_key)`, поэтому повторная доставка не увеличивает
счётчик. Сбой записи события не блокирует каталог, корзину или оплату.

Просмотры читаются через MTProto с `increment=False` раз в час. Это независимый
read-only контур: при недоступности Telegram сохраняются последние значения,
пишется структурированная ошибка и следующая попытка выполняется через час.
Ручное восстановление доступно кнопкой «Обновить просмотры» в разделе
`/publication-analytics`. Отключение feature flag прекращает новые события,
обновление просмотров и добавление ref-токенов, не затрагивая заказы.
